# KHI002: nint or IntPtr in an interop declaration

| Item     | Value                                |
| :------- | :----------------------------------- |
| Category | Interop                              |
| Severity | Error                                |
| Analyzer | `KappaDuck.Khaos.Internal.Analyzers` |

## Cause

A declaration in `Interop/SDL` or `Interop/Win32` uses `nint`: a method's return
value or parameter, a field or a property, in a struct or a class. The type is
reported wherever `nint` appears in it:

- `nint` itself, also passed as `ref`, `out` or `in`;
- a pointer to it, at any depth: `nint*`, `nint**`;
- a function pointer signature: `delegate* unmanaged<nint, void>`;
- the element of an `[InlineArray]` struct.

`nint` and `System.IntPtr` are the same type since C# 11.

## Why

An `nint` compiles wherever any other handle is expected. Nothing stops this:

```csharp
nint window = SDL3.CreateWindow("Pong", 1280, 720, 0);
SDL3.DestroyTexture(window);   // compiles
```

The error surfaces as a native crash, in a function that never received what it
thought it did. With a typed pointer the same line does not build.

## Reported

Return value:

```csharp
namespace KappaDuck.Khaos.Interop.SDL;

internal static unsafe partial class SDL3
{
    [LibraryImport("SDL3", EntryPoint = "SDL_GetWindowFromID")]
    internal static partial nint GetWindowFromID(SDL_WindowID id);
    //                    ~~~~ KHI002: The return value of 'GetWindowFromID' uses nint; type it as the
    //                         native pointer it carries, or wrap a pointer-sized integer in its own struct
}
```

Parameter, including a callback that native code calls:

```csharp
[LibraryImport("SDL3", EntryPoint = "SDL_DestroyWindow")]
internal static partial void DestroyWindow(nint window);
//                                         ~~~~ KHI002: Parameter 'window' of 'DestroyWindow' uses nint; …

[UnmanagedCallersOnly]
internal static byte Filter(nint userdata, SDL_Event* e) => 1;
//                          ~~~~ KHI002: Parameter 'userdata' of 'Filter' uses nint; …
```

Field or property, in a struct under `Primitives/` or anywhere else in the area:

```csharp
namespace KappaDuck.Khaos.Interop.SDL.Primitives;

internal struct SDL_Surface
{
    internal SDL_SurfaceFlags flags;
    internal nint pixels;
    //       ~~~~ KHI002: Field 'SDL_Surface.pixels' uses nint; …
}
```

On the Win32 side, same rule, same shape:

```csharp
namespace KappaDuck.Khaos.Interop.Win32.Primitives;

internal struct MENUITEMINFOW
{
    internal uint cbSize;
    internal nint hSubMenu;
    //       ~~~~ KHI002: Field 'MENUITEMINFOW.hSubMenu' uses nint; …
}
```

## Fix

A pointer takes its native type. A handle gets its own empty struct in
`Primitives/`, one per native type, and is used through a pointer:

```csharp
// Interop/SDL/Primitives/SDL_Window.cs
internal readonly struct SDL_Window;

[LibraryImport("SDL3", EntryPoint = "SDL_GetWindowFromID")]
internal static partial SDL_Window* GetWindowFromID(SDL_WindowID id);

[LibraryImport("SDL3", EntryPoint = "SDL_DestroyWindow")]
internal static partial void DestroyWindow(SDL_Window* window);
```

Win32 handles follow the same shape. `HMENU` is a `HANDLE`, which is a `void*`
([Windows Data Types]), so the C# `HMENU*` below is the C `HMENU`:

```csharp
// Interop/Win32/Primitives/HMENU.cs
internal readonly struct HMENU;

internal struct MENUITEMINFOW
{
    internal uint cbSize;
    internal HMENU* hSubMenu;
}
```

Memory that is untyped on the native side, such as pixel buffers or `userdata`,
takes `void*`. On a method, [KHI004](khi004.md) then asks for `[UntypedBecause]`
and its reason. KHI004 does not look at fields, so a `void* pixels` field needs
nothing more.

## A pointer-sized integer

Some native types are integers the size of a pointer, not pointers. Win32 has
`LPARAM` and `LRESULT`, both `LONG_PTR` ([Windows Data Types]), and every window
message carries them: `MSG.lParam` ([MSG]), the `MSG*` that a Windows message
hook receives ([SDL_WindowsMessageHook]), and the return value of
`DefWindowProcW` ([DefWindowProcW]). `nint` is their correct mapping.

Give each one its own struct whose only instance field is `nint`. KHI002 does
not report that struct, nor its members: the constructor and the conversions
are where the `nint` goes in and out.

```csharp
// Interop/Win32/Primitives/LPARAM.cs
internal readonly struct LPARAM
{
    internal readonly nint Value;

    internal LPARAM(nint value) => Value = value;
}

[LibraryImport("user32", EntryPoint = "DefWindowProcW")]
internal static partial LRESULT DefWindowProcW(HWND* hWnd, uint Msg, nuint wParam, LPARAM lParam);
```

The wrapper also keeps `LPARAM` and `LRESULT` from mixing, which a bare `nint`
would allow.

A struct with a second instance field is not a wrapper, and neither is an
`[InlineArray]` struct: its single field is the element of a buffer.

## Not reported

- **`nuint` and `UIntPtr`.** They are the correct mapping for `size_t`, which
  SDL uses for sizes and counts. `internal static partial nuint ReadIO(
  SDL_IOStream* context, void* ptr, nuint size);` is right, not a violation.
  Win32 `WPARAM` is a `UINT_PTR` and maps to `nuint` the same way.
- **Locals.** They are out of scope, which also settles `GCHandle.ToIntPtr`:
  it returns an `nint` by design, and it is the only way a managed object
  reaches a native `userdata`. The conversion to `void*` happens on the spot.
- **Constants.** C# has no constants of pointer type, so a native sentinel
  can only be a `const nint`, cast to its pointer type where it is used.
- **Arrays and generic arguments.** `nint[]` and `ReadOnlySpan<nint>` do not
  cross the native boundary as such.
- **Anything outside `Interop/SDL` and `Interop/Win32`.** A native handle
  deliberately exposed on the public surface, like `Window.Handle` for
  third-party interop, so the caller casts it to whatever their library
  expects. That is a public API decision, guarded by the architecture test and
  its explicit exception list, not by this rule.
- **Expressions.** `IntPtr.Zero` and `sizeof(nint)` are not declarations. They
  cannot exist without a declaration that is already reported.
- **The generated implementing half of a `[LibraryImport]` partial method.**
  Only the hand-written declaration is reported, because it is the one that can
  be fixed.

`fixed nint values[4]` does not need a rule: C# refuses `nint` as the element of
a fixed-size buffer (CS1663).

## Suppressing

Almost never. A pointer-sized integer takes a wrapper struct, not a suppression.
Suppress only a site the wrapper cannot express, and say why:

```csharp
[SuppressMessage("Interop", "KHI002", Justification = "...")]
```

If the suppression list grows past two or three, the rule is wrong and needs
revisiting, not more suppressions.
