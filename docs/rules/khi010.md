# KHI010: bool or char in a native callback

| Item     | Value                                |
| :------- | :----------------------------------- |
| Category | Interop                              |
| Severity | Error                                |
| Analyzer | `KappaDuck.Khaos.Internal.Analyzers` |

## Cause

A `bool` or a `char` appears in the signature of a native callback, anywhere in
the framework:

- the return value or a parameter of a method marked `[UnmanagedCallersOnly]`;
- the return value or a parameter of an unmanaged function pointer
  (`delegate* unmanaged<…>`, with or without a calling convention), used as the
  type of a field, a property, a return value or a parameter.

## Why

Native code calls an `[UnmanagedCallersOnly]` method without marshalling, so
its signature must be blittable. `bool` and `char` compile, but they are not
blittable, and since .NET 11, Native AOT stops the process when native code
calls such a method: "Native AOT throws InvalidProgramException if an unmanaged
caller invokes such a method with a non-blittable signature, such as a `bool`
return type or a `char` parameter. The exception causes the process to
terminate (fail fast) and can't be caught" ([Native AOT interop]).

Their native width is also not theirs to decide: an SDL callback returns a
1-byte `bool`, a Win32 callback a 4-byte `BOOL` ([KHI001](khi001.md)), and a
C `char` is 1 byte where a C# `char` is 2.

## Reported

`SDL_EventFilter` returns a C `bool` ([SDL_EventFilter]):

```csharp
namespace KappaDuck.Khaos.Interop.SDL;

internal static unsafe class EventFilter
{
    [UnmanagedCallersOnly]
    internal static bool Filter(void* userdata, SDL_Event* e) => true;
    //                   ~~~~~~ KHI010: 'Filter' has bool in a native callback signature; it is not
    //                          blittable and Native AOT stops the process on it, use byte or int
}
```

The same type in the function pointer that carries the callback:

```csharp
[LibraryImport(nameof(SDL3), EntryPoint = "SDL_SetEventFilter")]
[UntypedBecause("SDL hands userdata back to the filter untouched and never reads it")]
internal static partial void SetEventFilter(delegate* unmanaged<void*, SDL_Event*, bool> filter, void* userdata);
//                           ~~~~~~~~~~~~~~ KHI010: 'SetEventFilter' has bool in a native callback signature; …
```

## Fix

Use the blittable type of the native side: `byte` for an SDL `bool`, `int` for
a Win32 `BOOL`, `byte` for a C `char`, `ushort` for a Win32 `WCHAR`. Convert to
`bool` or `char` inside the callback.

```csharp
[UnmanagedCallersOnly]
internal static byte Filter(void* userdata, SDL_Event* e) => 1;

internal static partial void SetEventFilter(delegate* unmanaged<void*, SDL_Event*, byte> filter, void* userdata);
```

## Not reported

- **A pointer to them.** `bool*` and `char*` are blittable pointers; their
  width is [KHI011](khi011.md)'s business on the SDL side.
- **A managed function pointer.** `delegate*<bool, void>` never leaves .NET.
- **A method without `[UnmanagedCallersOnly]`.**
- **Locals and casts.** Only declarations are checked.

A `char` in an SDL callback is reported by this rule and by
[KHI011](khi011.md): two reasons, one fix.

## Suppressing

Never. The process stops the first time native code calls it.
