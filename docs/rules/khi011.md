# KHI011: char in Interop/SDL

| Item     | Value                                |
| :------- | :----------------------------------- |
| Category | Interop                              |
| Severity | Error                                |
| Analyzer | `KappaDuck.Khaos.Internal.Analyzers` |

## Cause

A declaration in `Interop/SDL` uses `char`: a field (a `fixed char` buffer and
an auto-property included), a property, or a method's return value or
parameter. The `char` is found at any pointer depth (`char*`) and inside a
function pointer.

## Why

A C `char` is 1 byte. A C# `char` is a 2-byte UTF-16 code unit
([char]). SDL strings are UTF-8 `const char*`, such as the title of
`SDL_CreateWindow` ([SDL_CreateWindow]).

Nothing fails when the width is wrong. A `char` field shifts every field after
it, and a `char*` reads two bytes per character, so the text comes out as noise
or runs past its terminator.

## Reported

```csharp
namespace KappaDuck.Khaos.Interop.SDL.Primitives;

internal unsafe struct SDL_TextInputEvent
{
    internal uint type;
    internal char* text;
    //       ~~~~~ KHI011: Field 'SDL_TextInputEvent.text' uses char; a C char is 1 byte
    //             in SDL, store it as byte
}
```

```csharp
[LibraryImport(nameof(SDL3), EntryPoint = "SDL_GetError")]
internal static partial char* GetError();
//                      ~~~~~ KHI011: The return value of 'GetError' uses char; …
```

## Fix

Store SDL text as `byte`, and decode it as UTF-8 in the wrapper.

```csharp
internal unsafe struct SDL_TextInputEvent
{
    internal uint type;
    internal byte* text;
}
```

## Not reported

- **`Interop/Win32`.** A Win32 `WCHAR` is a 2-byte UTF-16 unit, which is
  exactly a C# `char`.
- **A `const` field.** It is not part of a native layout.
- **`string`.** Its marshalling is decided by the custom SDL string
  marshallers, not by this rule.
- **Anything outside `Interop/SDL`.**

## Suppressing

Never. SDL text is UTF-8 bytes. The few `wchar_t` helpers, such as
`SDL_wcslen`, are no exception: "wchar_t is different sizes on different
platforms (4 bytes on Linux, 2 on Windows, etc)" ([SDL_wcslen]), so a C# `char`
is wrong for them on Linux too.
