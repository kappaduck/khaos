# KHI006: native library does not match its interop area

| Item     | Value                                |
| :------- | :----------------------------------- |
| Category | Interop                              |
| Severity | Error                                |
| Analyzer | `KappaDuck.Khaos.Internal.Analyzers` |

## Cause

The library named by `[LibraryImport]` does not belong to the interop area the
binding lives in, or belongs to no area at all.

| Area                            | Libraries                                      |
| :------------------------------ | :--------------------------------------------- |
| `KappaDuck.Khaos.Interop.SDL`   | `SDL3`, `SDL3_image`, `SDL3_ttf`, `SDL3_mixer` |
| `KappaDuck.Khaos.Interop.Win32` | `user32`, `kernel32`, `gdi32`                  |

The list lives in `InteropAreas`, next to the marshalling conventions, and it is
the only place that decides which DLLs Khaos binds.

## Why

This rule make sure libraries are in the good interop area. Also check underneath the other
two.

`KHI001` and `KHI002` both derive their answer from the area: `Interop/SDL`
means `UnmanagedType.U1`, `Interop/Win32` means `UnmanagedType.Bool`. A `user32`
binding that lands in `Interop/SDL` gets the SDL convention applied to its
`BOOL`s by a rule that believes it is right, and says nothing. The 4-byte value
is read one byte at a time, and the build is green.

The second failure is a library no area declares which turns "add a DLL" into a
deliberate one-line edit rather than a binding that lands wherever the file
happened to be open.

## Reported

Wrong area:

```csharp
namespace KappaDuck.Khaos.Interop.SDL;

internal static partial class SDL3
{
    [LibraryImport("user32", EntryPoint = "GetWindowTextLengthW")]
    //             ~~~~~~~~ KHI006: 'user32' does not belong to SDL; it belongs to Win32
    internal static partial int GetWindowTextLength();
}
```

And the other way around:

```csharp
namespace KappaDuck.Khaos.Interop.Win32;

internal static partial class User32
{
    [LibraryImport("SDL3", EntryPoint = "SDL_Quit")]
    //             ~~~~~~ KHI006: 'SDL3' does not belong to Win32; it belongs to SDL
    internal static partial void Quit();
}
```

Unknown library:

```csharp
namespace KappaDuck.Khaos.Interop.Win32;

internal static partial class Dwmapi
{
    [LibraryImport("dwmapi", EntryPoint = "DwmSetWindowAttribute")]
    //             ~~~~~~~~ KHI006: 'dwmapi' does not belong to Win32; no interop area declares it
    internal static partial int SetWindowAttribute();
}
```

## Fix

Move the binding to the area its library belongs to, into the file matching the
header that declares it.

For a library Khaos has never bound before, add it to its area in
`InteropAreas` first. That edit is the decision; the binding follows.

## Not reported

- **A library named through `nameof`.** `[LibraryImport(nameof(SDL3))]` carries
  the constant `"SDL3"` in metadata, so the rule reads it like any literal.
- **A case difference.** The comparison ignores case, because
  `nameof(User32)` is `"User32"` while the DLL is `user32`, and forcing the
  class to be named `user32` to satisfy a string comparison would be the tail
  wagging the dog. No two native libraries differ only by case.
- **Anything outside `Interop/SDL` and `Interop/Win32`.** A `[LibraryImport]`
  elsewhere in the framework has no area to be checked against and it should
  not exist in the first place, which is a different conversation.
- **The generated implementing half of a `[LibraryImport]` partial method.**
  Only the hand-written declaration is reported.

## Suppressing

Never. A binding whose library does not belong to its area is either in the
wrong folder or announcing a library nobody decided to bind. Both are fixed by
editing something, not by silencing the rule.
