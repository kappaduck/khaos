# KHI008: raw pointer on the public surface

| Item     | Value                                |
| :------- | :----------------------------------- |
| Category | Interop                              |
| Severity | Error                                |
| Analyzer | `KappaDuck.Khaos.Internal.Analyzers` |

## Cause

A member or a delegate type that is visible outside the assembly has a pointer,
a function pointer or an `nint` in its signature. Unlike the other rules, this
one looks at the whole framework, not only at `Interop/`: the leak happens where
the public surface is written.

It checks methods, constructors, operators, properties, indexers and fields, and
finds the type wherever it sits:

- the type itself, or a parameter passed as `ref`, `out` or `in`;
- the element of an array: `byte*[]`;
- for `nint` and `IntPtr`, a generic argument too: `IReadOnlyList<nint>`, `nint?`.

## Why

[KHI005](khi005.md) keeps every interop type internal, and the compiler then
refuses any public signature that mentions one. Some shapes get through that
net, because every part of them is a public type:

```csharp
public unsafe void* Pixels { get; }
public unsafe delegate* unmanaged<int, void> Callback;
public nint Handle { get; }
```

This rule closes them. A game should never hold a pointer or a native handle
that Khaos owns: the lifetime is not theirs, and nothing stops them from using
it after the renderer is gone. An `nint` is no safer than a pointer here: it
compiles wherever any handle is expected ([KHI002](khi002.md)).

A pointer can never be a generic argument (CS0306, [generic type parameter
errors]), so only `nint` is looked for inside one.

## Reported

```csharp
namespace KappaDuck.Khaos.Windowing;

public sealed unsafe class Window
{
    public void* Handle { get; }
    //           ~~~~~~ KHI008: 'Window.Handle' exposes a raw pointer;
    //                  the pointer stays behind the wrapper
}
```

```csharp
public sealed class Window
{
    public nint Handle { get; }
    //          ~~~~~~ KHI008: 'Window.Handle' exposes nint; wrap the native handle
    //                 in a type that represents it
}
```

A public delegate type is reported on its name:

```csharp
public unsafe delegate void PixelCallback(byte* pixels);
//                          ~~~~~~~~~~~~~ KHI008: 'PixelCallback' exposes a raw pointer; …
```

## Fix

Keep the pointer in a private field and expose what the caller actually needs.

When the caller genuinely needs the native handle, such as an overlay attaching
to the window or a video player, expose a `WindowHandle`: the one type that
represents the handles of each platform. It is the only place the raw values
appear, and it says so with a suppression.

```csharp
public sealed unsafe class Window
{
    private SDL_Window* _window;

    public WindowHandle Handle => ...;
}

public readonly struct WindowHandle
{
    [SuppressMessage("Interop", "KHI008", Justification = "The one native handle Khaos hands out, for overlays and video players.")]
    public nint Hwnd { get; }
}
```

## Not reported

- **`nuint`.** It maps sizes and counts, not handles.
- **A member that does not leave the assembly**, including a `public` member of
  an `internal` type, and an `internal` or `private protected` member of a
  `public` type.
- **A property accessor.** The property is reported once, not three times.

## Suppressing

Only on a type that represents a native handle, such as `WindowHandle`, with a
justification that says who needs the raw value. Anywhere else, the pointer
stays behind the wrapper.

[generic type parameter errors]: https://learn.microsoft.com/dotnet/csharp/language-reference/compiler-messages/generic-type-parameters-errors
