# KHI004: void* without a stated reason

| Item     | Value                                |
| :------- | :----------------------------------- |
| Category | Interop                              |
| Severity | Error                                |
| Analyzer | `KappaDuck.Khaos.Internal.Analyzers` |

## Cause

A method in `Interop/SDL` or `Interop/Win32` takes or returns `void*` and does
not carry `[UntypedBecause]` with a non-empty reason. Every method counts: a
`[LibraryImport]`, a callback marked `[UnmanagedCallersOnly]`, a helper, a
constructor or an operator.

The `void*` is found wherever it sits in the signature:

- a parameter or the return value, also passed as `ref`, `out` or `in`;
- at any level of indirection: `void**`;
- inside a function pointer: `delegate* unmanaged<void*, void>`.

## Why

`void*` is the right answer when the native side is genuinely untyped, and the
wrong answer when the real type is simply unknown. The two look identical in
the source. A written reason separates them: a `userdata` pointer SDL hands back
untouched has one, a handle nobody looked up on the wiki does not.

The reason is an attribute rather than a comment so that it survives a reformat,
can be found by searching, and cannot be satisfied by typing `// void*`. Its
name reads as the start of the sentence it asks for: untyped because…

It sits on the method rather than on the parameter because that is where the
decision was made, and because one sentence usually covers the whole signature.

## Reported

`SDL_SetEventFilter` takes a filter and the `userdata` handed to it, both
untyped on the native side ([SDL_SetEventFilter], [SDL_EventFilter]):

```csharp
namespace KappaDuck.Khaos.Interop.SDL;

internal static unsafe partial class SDL3
{
    [LibraryImport(nameof(SDL3), EntryPoint = "SDL_SetEventFilter")]
    internal static partial void SetEventFilter(delegate* unmanaged<void*, SDL_Event*, byte> filter, void* userdata);
    //                           ~~~~~~~~~~~~~~ KHI004: 'SetEventFilter' takes or returns void*
    //                                          without [UntypedBecause]; say why it cannot be typed
}
```

An empty or whitespace reason is not a reason. It is reported on the argument:

```csharp
[UntypedBecause("")]
//              ~~ KHI004: 'SetEventFilter' gives [UntypedBecause] an empty reason; say why it cannot be typed
```

## Fix

```csharp
[LibraryImport(nameof(SDL3), EntryPoint = "SDL_SetEventFilter")]
[UntypedBecause("SDL hands userdata back to the filter untouched and never reads it")]
internal static partial void SetEventFilter(delegate* unmanaged<void*, SDL_Event*, byte> filter, void* userdata);
```

`UntypedBecauseAttribute` lives at the root of `Interop`, and is `internal` like
everything there ([KHI005](khi005.md)).

If no such sentence can be written, the pointer has a type and it has not been
looked up yet. That is the case the rule exists for.

## Not reported

- **A typed pointer.** `SDL_Window*` says what it carries.
- **A `void` return.** `void Quit()` returns nothing; only `void*` is untyped.
- **A `void*` field.** The attribute targets methods; a struct that stores
  untyped memory documents it where the struct is declared.
- **A `void*` outside `Interop/SDL` and `Interop/Win32`.**
- **The generated implementing half of a partial method.**

## Suppressing

Never. The suppression would take more characters than the reason.
