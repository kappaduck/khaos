# KHI007: bool in an interop struct

| Item | Value |
| :-- | :-- |
| Category | Interop |
| Severity | Error |
| Analyzer | `KappaDuck.Khaos.Internal.Analyzers` |

## Cause

An instance field of a struct in `Interop/SDL` or `Interop/Win32` is declared
`bool`.

| Area | Native type | Store it as |
| :-- | :-- | :-- |
| `KappaDuck.Khaos.Interop.SDL` | `bool` (C99, 1 byte) | `byte` |
| `KappaDuck.Khaos.Interop.Win32` | `BOOL` (`typedef int`, 4 bytes) | `int` |

## Why

`bool` is not blittable: its native width is decided when it is marshalled, not
by its managed layout. A struct that holds one therefore requires marshalling,
and that breaks in two different ways depending on how the struct is used.

**Passed by value to a `[LibraryImport]` method.** The generator writes its
marshalling code at compile time and handles blittable structs or a custom
marshaller. It refuses the struct, and suggests disabling runtime
marshalling for the whole assembly. Khaos does not take that trade: disabled
runtime marshalling also removes `in`, `ref` and `out` parameters and
`SetLastError`, which is a large bill for one field. `[MarshalAs]` on the field
does not help either, because the struct stays non-blittable.

## Reported

```csharp
namespace KappaDuck.Khaos.Interop.SDL.Primitives;

internal struct SDL_KeyboardEvent
{
    internal bool down;
    //       ~~~~ KHI007: Field 'SDL_KeyboardEvent.down' is declared as bool;
    //            in SDL a native boolean is stored as byte
}
```

An annotation does not silence it, because it is not the fix:

```csharp
namespace KappaDuck.Khaos.Interop.Win32.Primitives;

internal struct PAINTSTRUCT
{
    [MarshalAs(UnmanagedType.Bool)]
    internal bool fErase;
    //       ~~~~ KHI007: Field 'PAINTSTRUCT.fErase' is declared as bool;
    //            in Win32 a native boolean is stored as int
}
```

## Fix

```csharp
internal struct SDL_KeyboardEvent
{
    internal byte down;
}

internal struct PAINTSTRUCT
{
    internal int fErase;
}
```

The `bool` belongs on the public wrapper, which converts once:

```csharp
public readonly struct KeyPressed
{
    internal KeyPressed(in SDL_KeyboardEvent e)
    {
        Scancode = e.scancode;
        IsRepeat = e.repeat != 0;
    }

    public Scancode Scancode { get; }

    public bool IsRepeat { get; }
}
```

A one-byte `readonly struct` wrapper with implicit conversions is an acceptable
alternative to a bare `byte` on the SDL side, as long as it stays blittable. It
buys readability at the field level; decide it once, for the whole folder.

## Not reported

- A `const` or `static` field. Neither is part of the struct's native layout.
- A `bool` field in a class. Only structs describe native layout.
- Anything outside `Interop/SDL` and `Interop/Win32`.

## Suppressing

There is no good reason. If a native struct really does hold a 1-byte boolean on
the Win32 side (`BOOLEAN` rather than `BOOL`), the field is a `byte`, which this
rule already accepts — no suppression needed.
