# KHI003: LibraryImport without an explicit EntryPoint

| Item     | Value                                |
| :------- | :----------------------------------- |
| Category | Interop                              |
| Severity | Error                                |
| Analyzer | `KappaDuck.Khaos.Internal.Analyzers` |

## Cause

A `[LibraryImport]` inside an interop area does not set `EntryPoint`, or sets it
to an empty string.

## Why

The managed name drops the library prefix, so nothing left in the declaration
says which native symbol is being bound. `EntryPoint` is that link, and it is
what makes a binding searchable against the wiki page it came from.

It is written even when it would match the managed name. A name that happens to
match today stops matching the first time someone renames the method, and the
rename compiles.

## Reported

```csharp
namespace KappaDuck.Khaos.Interop.SDL;

internal static partial class SDL3
{
    [LibraryImport(nameof(SDL3))]
    // ~~~~~~~~~~~~~~~~~~~~~~~~~ KHI003: 'Quit' does not set EntryPoint; name the native symbol it binds
    internal static partial void Quit();
}
```

## Fix

```csharp
[LibraryImport(nameof(SDL3), EntryPoint = "SDL_Quit")]
internal static partial void Quit();
```

## Not reported

- **A `[LibraryImport]` outside `Interop/SDL` and `Interop/Win32`.** It should
  not exist there in the first place, which is a different conversation.
- **The generated implementing half of a partial method.** Only the hand-written
  declaration is reported.

## Suppressing

Never. Writing the native symbol down costs one string.
