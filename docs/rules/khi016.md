# KHI016: native event type claimed by two cases

| Item     | Value                                |
| :------- | :----------------------------------- |
| Category | Events                               |
| Severity | Error                                |
| Analyzer | `KappaDuck.Khaos.Internal.Analyzers` |

## Cause

Two `[KhaosEvent]` cases claim the same native event type, or a case claims a type inside the range of another,
such as a type between `SDL_EventType.User` and `SDL_EventType.Last`, which `CustomEvent` already covers.

## Why

The converter switches on the native type, and one native event becomes one case. The generator sorts the cases by
their first native type, then by name, keeps the first, and leaves the other out of `Event`: the game would never
receive it. The rule is reported on the case that is left out.

It needs every case of the compilation, so it is reported once the whole compilation is analyzed: the build always
shows it, and the editor shows it after a full analysis.

## Reported

```csharp
[KhaosEvent(SDL_EventType.Quit)]
public readonly record struct QuitRequested;

[KhaosEvent(SDL_EventType.Quit)]
public readonly record struct GameClosing;
//                            ~~~~~~~~~~~ KHI016: 'GameClosing' claims a native event type that
//                                        'QuitRequested' already converts
```

## Fix

Keep one case per native type. When two meanings share a native type, one case carries what tells them apart:

```csharp
[KhaosEvent(SDL_EventType.KeyDown)]
public readonly record struct KeyPressed(Scancode Code);
```

## Suppressing

Never. One of the two cases is never received.
